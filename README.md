## 🏭 行业定制规划（分类 ⑥）

**方案演练 · 高分子新材料行业信息化规划（示例）**

> **性质：能力演练 / 非客户委托 · 未涉及任何客户数据**

按一份真实招聘 JD 与该行业公开资料编写的<b>能力演练稿</b>（建筑密封胶行业，国标起草单位为其行业公开信息）。以「入职后规划」视角，覆盖 ERP / SRM / PLM / MES / HR / LIMS 五大业务系统 + 数据中台 + AI 能力平台 + 基础设施安全，并深度融入 AIGC 与 AI Agent 落地场景。

- **体系化规划**：L1-L5 成熟度模型 + 总体蓝图 + 按系统完善程度推进的优先级矩阵
- **行业深度适配**：配方研发 Copilot、多标准合规核查、批次质量追溯等 8 个专属 AI 场景
- **财务方向强项**：业财一体化、研发费用归集与加计扣除，契合高新技术企业真实需求

> 对应岗位：AI 项目经理（规划主线）· FDE（现场诊断与交付）。演示方式：可提供脱敏版规划书，现场逐页讲解规划逻辑与优先级取舍。

## 🛠 技术栈与实现

- **前端**：纯静态 HTML + CSS + 原生 JavaScript，零框架依赖，加载快
- **Markdown 渲染**：marked.js 实现 .md 文件优雅展示（弹模态框）
- **部署**：GitHub Pages（Deploy from a branch, main / root）
- **数据**：所有作品集内容以 JS 数组形式内嵌于 `index.html`，便于维护
- **附件**：PDF / DOCX / XLSX / PNG / SVG / MD 等原始材料按模块分文件夹归档

## ➕ 新增作品（一条命令上线）

作品数据以 `works-data.json` 为**唯一编辑口**。新增作品只需在 `items` 里追加一条对象，
**不用写编号**（会自动顺延），然后跑一条命令：

```bash
node build.mjs          # 构建 + 自检，不推送
node build.mjs --ship   # 构建通过后直接提交并推送，约 2-3 分钟上线
```

`build.mjs` 会依次完成：`patch-works` → `enrich-works` → `inline-preview` →
产物一致性校验 → 编号连续性校验 → 卡片几何自检（桌面 / 移动 / 首页）。
**任何一步失败都会立刻停下，不会把坏页面推上线。**

新作品的最小字段：

```jsonc
{
  "t": "作品标题",           // 必填
  "cat": "agent",           // 必填：plan / flow / agent / data / oss / industry
  "status": "已发布",
  "jd": "AI 智能体开发工程师",
  "pitch": "一句话说清做成了什么",
  "highlights": [{ "num": "3 个", "label": "关键指标" }],
  "tags": ["MCP", "LangGraph"],
  "links": ["GitHub 仓库：xxx|https://github.com/Jav1es/xxx"],
  "role": "我负责什么",      // 可选：不写则「展开详情」只有摘要
  "arch": "架构 / 方案",     // 可选
  "steps": ["第一步", "第二步"], // 可选
  "pain": "解决的痛点"        // 可选
}
```

- **编号**：不写 `no` 就自动取当前最大编号 +1；写了则保留（用于插到指定位置）。
- **分组**：不写 `group` 就按 `cat` 自动归入（`agent`/`data`→AI 工程化，
  `oss`→开源工具，`plan`/`flow`/`industry`→核心案例）。
- 每个新增作品都会自动进入首页精选区与岗位页，无需手工改任何 HTML。

> 数据管线原本依赖 `.dsh-workspace/artifacts/legacy-singlepage.html`（旧单页，未入库）。
> 现在该文件**只在首次全量重建时需要**，日常新增作品直接改 `works-data.json` 即可。
