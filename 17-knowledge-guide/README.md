> **开源仓库**：https://github.com/Jav1es/dsh-knowledge-guide （MIT）
> **规程全文**：[knowledge-guide-SKILL.md](./knowledge-guide-SKILL.md)（即仓库里的 `SKILL.md`，frontmatter 原样保留）

## 一句话

把「先检索再作答、强制标来源、置信度标注、未命中先做正对照」从每次会话的临场发挥，
变成一份可复用、可审计的规程。

## 为什么需要它

**DSH 里没有自动上下文检索。** 除了 `AGENTS.md`，一切知识都得主动调工具才会进上下文。
这意味着：

| 现状 | 后果 |
|---|---|
| 模型有训练数据截止日期 | 问「最新现状」「某公司某产品」时凭记忆作答 = 编造 |
| 知识不进上下文 | 不主动调工具就等于没检索，而「忘了调」是最常见的失败模式 |
| 回答无来源 | 无法验证，错误无法定位，对外材料引用错数字就是事故 |
| 「查不到」不可信 | 检索通道故障与内容不存在都表现为搜不到，分不清就会把「没查」误当「没有」 |

规程针对的就是这四点：**路由 / 标注 / 证伪 / 降级**。

## 规程结构

```
第一步  判断问题类型 ─→ 本地事实 / 外部现状 / 深度调研 / 推理写作
第二步  检索路由     ─→ 本地优先于联网；外部检索走 AnySearch 垂直库
第三步  回答格式     ─→ 结论先行 + 每点标来源 + 证据强度（高 / 中 / 低）
```

核心断言：**没检索过就不作答。**

例外写死在规程里（纯概念解释 / 纯代码任务 / 用户明确说「就聊聊」），
避免把「凡事必查」变成另一种浪费。

## 三路检索通道

| 路 | 工具 | 覆盖 |
|---|---|---|
| 文件 | `read` / `grep` / `glob` | 项目约定、HANDOFF、配置事实 |
| TiddlyWiki | `tiddlywiki_search` 等 15 个工具 | DSH 运维与集成案例（长期记忆） |
| 外部 | AnySearch | 当前、外部、变化的现状（7 类垂直库） |

## ⚠️ 诚实披露：这不是向量 RAG

DSH 自带的 `knowledge` 库**当前是空的**，本模块也没用它：

- `~/.dsh/knowledge/knowledge.sqlite` 共 **18 张表**，但 `knowledge_documents` **0 篇**、
  `knowledge_entries` **0 条**、`knowledge_mounts` **0 个挂载**（`knowledge_bases` 表有 1 行占位）；
- 对应插件**未安装**（装它会因 peer 依赖带 5 个 `@deepseek-ai/*` 运行时内置包 → 双实例 → 崩溃）。

所以走的是**文件 + TiddlyWiki + AnySearch 三路**，**不是向量 RAG、不做 embedding、不做语义召回**。
本地知识是**文件式**的 —— 这正是规程的设计前提。

## 能力测试

新开会话、不加任何提示，跑三道真实工作题，验证检索纪律**真实执行**而非只写在文件里；
随后做升档审计（`deepseek-v4-pro`）并产出笔记。

> 审计确实抓出一处归因错误：原笔记把「cost-meter 对 space-bunny 定价缺失」归因于账本缺价目，
> 实测账本里**有** `space-bunny-free` 行（源 opencode.ai）——即上游把该模型标成 `-free` 档，
> 不是账本缺价目。同时 `credits.total` 从 424 → 395，证明该模型**确实在扣积分**。
> 这条订正正是「强制标来源 + 跨源验证」规程的直接产出。

## 本机坑位清单（节选）

1. **不要装 `dsh-knowledge` 插件** —— peer 依赖双实例即崩。
2. **web seam 无 provider 兜底链** —— 配置命中即用，不可用就抛错，不 fallback。
3. **换模型代价被低估** —— 切换 = KV cache 全失效 + 上下文重算，且目标档倍率再乘一遍。
4. **别为「看图」切 glm-5.2/5.3** —— 昂贵通用档**且看不了图**（投递问题，非模型能力问题）。
5. **改配置要在会话开始前做** —— 会话中途改 patch = 摧毁缓存前缀。
6. **「不存在 / 没有」先做正对照** —— 拿一个已知存在的项验证通道有效性，再下结论。
